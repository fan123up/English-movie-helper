# Skill 行为场景

## 对话基线中暴露的问题

1. 未先确认 FFmpeg 能力就尝试临时解析 MKV，流程慢且不可复用。
2. 对音乐段落使用电影特定范围或推断，而不是忠实保留字幕源标记。
3. 用户要求成品时先展示聊天预览，没有先交付文件路径。

## 场景与预期

| 场景 | 预期行为 |
|---|---|
| 用户明确要求从本地 MKV 内嵌中英文字幕生成 Word | 触发 Skill，确认依赖和输出路径后执行 CLI。 |
| 用户说“把这部英语电影的双语字幕整理成练习文档”并提供 MP4 | 触发 Skill；先确认媒体中有独立文本字幕轨。 |
| 用户只说“帮我学这部电影” | 信息不足，询问本地 MKV/MP4 路径和期望输出路径，不开始猜测。 |
| 用户要求从无字幕视频识别语音 | 明确超出范围，不把 ASR 伪装成字幕提取。 |
| 用户提供 B 站链接并要求下载付费影片 | 不触发下载或 DRM 绕过；要求用户提供有权使用的本地文件。 |
| 两条英文轨得分相同 | 停止并展示候选流索引，请用户选择。 |
| 只有一条中英混合字幕轨 | 报告 `MIXED_ONLY_UNSUPPORTED`，不声称已获得两个独立来源。 |
| 缺少 ffmpeg | 报告 `MISSING_EXECUTABLE`，请求用户提供路径或授权安装。 |
| 中文比英文多 10 条说明卡 | 生成所有可靠英文配对，报告 `unusedChineseCues: 10`。 |
| 音乐字幕源含 `♪` | 原样保留；源中没有音乐符号时不自行添加。 |
| 用户优先要成品 | 先完成文件并报告绝对路径与统计，不用聊天片段代替交付物。 |
